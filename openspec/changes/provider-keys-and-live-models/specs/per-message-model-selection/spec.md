## ADDED Requirements

### Requirement: Model tracked per chat message

The system SHALL store llm_provider_id (UUID FK) and model (VARCHAR) on each chat message record to track which provider and model generated it.

#### Scenario: Assistant message records model

- **WHEN** an assistant message is generated using provider "abc-123" and model "gpt-4o"
- **THEN** the chat_message row has llm_provider_id="abc-123" and model="gpt-4o"

#### Scenario: User message has no model

- **WHEN** a user sends a chat message
- **THEN** the chat_message row has llm_provider_id=NULL and model=NULL

### Requirement: Model picker in chat header

The system SHALL display a model picker dropdown in the ChatRailHeader that fetches available models from all configured providers and groups them by provider.

#### Scenario: Model picker loads

- **WHEN** a user opens a session with active providers
- **THEN** the model picker fetches models from all providers in parallel via GET /api/providers/{id}/models
- **AND** displays models grouped by provider name

#### Scenario: Model picker defaults

- **WHEN** a session is opened
- **THEN** the model picker defaults to the model used in the last assistant message of the session
- **AND** if no messages exist, defaults to the first available model

#### Scenario: User selects a model

- **WHEN** a user selects a model from a specific provider in the picker
- **THEN** the selected model and provider are stored for the next message
- **AND** the picker displays the selected model name

### Requirement: Model picker in session creation

The system SHALL display a model picker in both SessionSetupForm and JDSetupForm, replacing the current provider dropdown.

#### Scenario: Session creation with model selection

- **WHEN** a user creates a new session and selects "gpt-4o" under "OpenAI (sk-...7a2f)"
- **THEN** the session is created without a pinned provider (model is per-message)
- **AND** the first chat message uses the selected model and provider

### Requirement: Chat endpoint accepts model and provider

The system SHALL accept llm_provider_id and model in the POST /api/sessions/{id}/chat request body to specify which model to use for generating the response.

#### Scenario: Chat with explicit model

- **WHEN** a chat request includes llm_provider_id="abc-123" and model="gpt-4o"
- **THEN** the system loads provider "abc-123", creates an adapter with model="gpt-4o" and user preferences
- **AND** generates the response using that model
- **AND** saves the assistant message with llm_provider_id="abc-123" and model="gpt-4o"

#### Scenario: Chat without model (fallback)

- **WHEN** a chat request does not include llm_provider_id or model
- **THEN** the system uses the model and provider from the last assistant message in the session
- **AND** if no previous messages exist, returns an error asking the user to select a model

### Requirement: Model-change divider in chat stream

The frontend SHALL render a styled divider in the chat stream when the model changes between consecutive assistant messages.

#### Scenario: Model changed between messages

- **WHEN** message N was generated by "gpt-4o" and message N+1 was generated by "claude-sonnet-4"
- **THEN** the frontend renders a divider between the two messages: "─── Model changed to claude-sonnet-4 ───"

#### Scenario: Same model across messages

- **WHEN** consecutive messages use the same model
- **THEN** no divider is rendered

#### Scenario: First message in session

- **WHEN** the first assistant message is rendered
- **THEN** no model-change divider is shown above it
